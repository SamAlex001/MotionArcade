B.  TIMING — HOW 60 FPS AND ASYNC AI COEXIST
════════════════════════════════════════════════════════════════════════════════

  TIME ──────────────────────────────────────────────────────────────────────▶
       0         250ms        500ms        750ms       1000ms       1250ms

  MediaPipe
  inference   ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌ ▐█▌
  (~10ms ea)  each block = one detectForVideo() — runs continuously, always

  landmarksRef
  updated:    ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑
              every frame — zero React overhead, game reads this in rAF

  detectedFingers
  state:      ↑                   ↑                             ↑
              only fires when the integer finger count changes

  landmarks
  state:      ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑
              20 Hz heartbeat (every 50ms) — drives canvas useEffect

  Gemini AI   ├───────────────────────────────────────────────────┤
  round-trip  request sent ~0ms                  response ~1100ms
  (~800–1500ms)      (state = LOADING_PROBLEM, spinner shown to user)

  Game state  PLAYING ────────── HOLDING ──── FEEDBACK ── LOADING ── PLAYING
                                  (3s hold)    (2s)        (AI wait)
                                  ^                        ^
                                  gesture detected         question received

  KEY INSIGHT:  While Gemini awaits, the MediaPipe loop continues at
  full speed — 60 frames of inference fire during a 1-second AI call.
  The two clocks are completely independent.

         │                            │
         ▼                            ▼
  ┌──────────────────┐    ┌───────────────────────────┐
  │  Read in rAF     │    │  Read in useEffect        │
  │                  │    │                           │
  │  • Canvas draw   │    │  • Answer selection       │
  │  • Collision     │    │  • Game state machine     │
  │    detection     │    │  • Canvas overlay render  │

  │                  │    │                           │

  └──────────────────┘    └───────────────────────────┘

  WHY TWO TRACKS?
  Calling setState 60× per second triggered React's "Maximum update
  depth exceeded" in the original implementation. Refs bypass React's
  scheduler entirely — always fresh, zero cost.

E.  FINGER COUNTING ALGORITHM  (cosine similarity)
════════════════════════════════════════════════════════════════════════════════

  GEOMETRY — side view of one finger:

         EXTENDED                      CURLED
         ────────                      ──────
           [c] TIP                       ──[a] MCP
             │                          /
        u ↑ [b] PIP ↓ v             [b] PIP
             │                            \
           [a] MCP                         [c] TIP

    u = a − b   v = c − b
    Extended: u and v are nearly opposite → cos ≈ −1.0
    Curled:   u and v are at an angle     → cos ≈ +0.5

    cos(angle) = dot(u,v) / (|u| × |v|)

  THRESHOLDS:
    Regular fingers:  cos < −0.9397  (angle > 160°)  →  EXTENDED
    Thumb:            cos < −0.8660  (angle > 150°)  →  EXTENDED

  LANDMARK INDEX TABLE:
  ┌───────────┬──────────────────────┬───────┬───────┬──────┬────────────┐
  │  Finger   │  Triple (a, b, c)    │   a   │   b   │   c  │ Threshold  │
  ├───────────┼──────────────────────┼───────┼───────┼──────┼────────────┤
  │  Index    │  MCP → PIP → Tip     │   5   │   6   │   8  │  −0.9397   │
  │  Middle   │  MCP → PIP → Tip     │   9   │  10   │  12  │  −0.9397   │
  │  Ring     │  MCP → PIP → Tip     │  13   │  14   │  16  │  −0.9397   │
  │  Pinky    │  MCP → PIP → Tip     │  17   │  18   │  20  │  −0.9397   │
  │  Thumb    │  CMC → MCP → IP      │   1   │   2   │   3  │  −0.8660   │
  └───────────┴──────────────────────┴───────┴───────┴──────┴────────────┘

  PERFORMANCE vs. atan2 (original approach):
  ┌────────────────────────────┬─────────────┬──────────────────────────┐
  │  Method                    │  Cost/joint │  At 60fps, 2 hands       │
  ├────────────────────────────┼─────────────┼──────────────────────────┤
  │  Math.atan2  (original)    │   ~120 ns   │  ~144,000 ns  = 0.14 ms  │
  │  cosine similarity (now)   │     ~5 ns   │    ~6,000 ns  = 0.006 ms │
  │  Speedup                   │     24×     │  saves ~0.13ms/frame     │
  └────────────────────────────┴─────────────┴──────────────────────────┘

  10 isStraight() calls per frame (5 fingers × 2 hands):
    each call = 4 subtractions + 1 dot product + 1 sqrt + 1 compare

F.  VIDEO-TO-CANVAS COORDINATE MAPPING  (object-fit: cover)
════════════════════════════════════════════════════════════════════════════════

  Example: video frame = 1280×720,  display container = 400×533

  STEP 1 — MediaPipe normalized space  (what detectForVideo returns)
  ┌──────────────────────────────────────────┐
  │ (0,0)                          (1,0)     │
  │                                          │
  │              ● landmark                  │
  │            (0.5, 0.3)                    │
  │                                          │
  │ (0,1)                          (1,1)     │
  └──────────────────────────────────────────┘
  videoWidth = 1280,  videoHeight = 720

  STEP 2 — object-fit: cover scale computation
  scale   = max(displayW / videoW,  displayH / videoH)
          = max(400/1280,  533/720)
          = max(0.3125,  0.7403)
          = 0.7403

  scaledW = 1280 × 0.7403 = 947 px   ← wider than container → cropped
  scaledH =  720 × 0.7403 = 533 px   ← exactly fills container height
  offsetX = (947 − 400) / 2 = 273 px
  offsetY = (533 − 533) / 2 =   0 px

  STEP 3 — Visible area after cover-crop
  ┌──────────────────────────────────────────────────────────────────┐
  │◄── 273px ──►┌──────────────────────┐◄── 273px ──────────────────►│
  │  (cropped)  │  visible: 400×533    │  (cropped)                  │
  │             │                      │                              │
  │             │        ●             │                              │
  │             │      landmark        │                              │
  │             └──────────────────────┘                              │
  │◄─────────────── scaledW = 947px ──────────────────────────────────►│
  └──────────────────────────────────────────────────────────────────┘

  STEP 4 — Convert to pixel, apply mirror
  raw_x    = landmark.x × scaledW − offsetX  =  0.5 × 947 − 273  = 200.5
  raw_y    = landmark.y × scaledH − offsetY  =  0.3 × 533 −   0  = 159.9
  mirror_x = displayW − raw_x               =  400 − 200.5       = 199.5

  canvas point = (199.5, 159.9)

  CACHE:  Results stored in WeakMap<HTMLVideoElement, CachedMapping>.
  Invalidated only when videoWidth / videoHeight / clientWidth / clientHeight
  change.  At 60fps with 42 landmarks, this eliminates 41 redundant DOM reads
  per frame — only the first landmark call touches the DOM.

════════════════════════════════════════════════════════════════════════════════
J.  ADAPTIVE FRAME SKIPPING
════════════════════════════════════════════════════════════════════════════════

  Frame budget:  16.7ms desktop (60fps)  |  33ms mobile (30fps)

  skipFrames adaptation:
    dt > budget × 1.5  →  skipFrames++   (max 3)
    dt < budget × 0.6  →  skipFrames--   (min 0)

  effective_skip = (isMobile ? 1 : 0) + skipFrames

  DESKTOP  (budget = 16.7ms)
  ──────────────────────────────────────────────────────────────────
  skipFrames = 0  →  run every frame
  ▐RUN▌▐RUN▌▐RUN▌▐RUN▌▐RUN▌▐RUN▌▐RUN▌▐RUN▌
  FPS: 60

  skipFrames = 1  →  run every 2nd frame  (thermal throttle kicks in)
  ▐RUN▌     ▐RUN▌     ▐RUN▌     ▐RUN▌
       skip       skip       skip       skip
  FPS: 30

  skipFrames = 2  →  run every 3rd frame  (heavier throttle)
  ▐RUN▌          ▐RUN▌          ▐RUN▌
       skip  skip      skip  skip      skip  skip
  FPS: 20

  skipFrames = 3  →  run every 4th frame  (emergency mode)
  ▐RUN▌               ▐RUN▌               ▐RUN▌
       skip  skip  skip      skip  skip  skip
  FPS: 15

  MOBILE  (always starts with +1 implicit skip)
  ──────────────────────────────────────────────────────────────────
  skipFrames = 0 + mobile bonus  →  effective 1  →  30fps baseline
  ▐RUN▌     ▐RUN▌     ▐RUN▌     ▐RUN▌
  FPS: 30

  skipFrames = 1 + mobile bonus  →  effective 2  →  20fps
  ▐RUN▌          ▐RUN▌          ▐RUN▌
  FPS: 20

  Skip count auto-recovers when device cools down or scene simplifies.
