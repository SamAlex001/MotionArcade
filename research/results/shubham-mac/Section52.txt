================================================================

  Q1  Average FPS during gameplay
      A: ~120 fps across all games, frame-pace locked to the
         120 Hz display. The optimised render loop runs well
         within the 8.33 ms per-frame budget.

  Q2  Browser RAM during gameplay
      A: ~245 MB per Chrome tab (Three.js scene + MediaPipe
         WASM + React 18 + game state).

  Q3  Average Chrome CPU during gameplay
      A: 25-32% as reported by Chrome's per-tab Task Manager
         on this machine. The cost is dominated by MediaPipe
         inference at 6.7-9.3 ms per frame, with Three.js render
         and Canvas-2D draw at sub-millisecond p50.

  Q4  Gemini API median response time
      A: 2.33 seconds median across the four AI game flows
         (15 calls). Range 1.2-6.1 s. Quiz flow is fastest
         (1.3 s typical); Math Challenge 2 is slowest (2.8 s
         median).

     worst max  : 43.6 ms (one GC/thermal blip)

Interpretation: the MediaPipe hand-landmarker model is the
dominant per-frame cost on this machine. The optimised JavaScript
glue (finger-counting, coordinate mapping, Three.js draw,
Canvas-2D draw) all measure at sub-millisecond p50, well under
1% of the 8.33 ms frame budget. The hypothesis that JS glue was
the original bottleneck is confirmed in shape: the post-
optimisation system is bottlenecked only by model inference,
which is the desired end state.

Notes
  - The Quiz flow's 6,127 ms max is one tail-latency outlier;
    excluding it the mean drops to ~1,278 ms.
  - Free-tier rate limits observed during sampling:

        warmed  : 20 requests/min

    queuing, not a host or network issue.

User-visible takeaway: a new AI-generated question or shape
arrives in roughly 1-3 seconds typically, with occasional
5-6 second outliers under upstream congestion.

5.2.7  JAVASCRIPT MICROBENCHMARK (atan2 vs cosine)
================================================================

Subject : the per-frame finger-angle test, rewritten from
          Math.atan2 (two calls per joint) to a cosine via
          dot product.
Method  : 5 runs of 5,000,000 iterations each, two hands
          (21 landmarks each) per call.

  +-----------------------+--------+----------+--------+--------+
  | Implementation        |   min  |  median  |  mean  |   max  |
  +-----------------------+--------+----------+--------+--------+
  | Baseline (atan2)      | 130.4  |  131.7   | 132.0  | 133.3  |
  | Optimised (cosine)    |  29.3  |   29.6   |  29.9  |  31.1  |
  +-----------------------+--------+----------+--------+--------+
  (ns per countFingers call; 2 hands per call)

  Speedup: 4.44x.

Both forms run in <1% of an 8.3 ms frame budget, so the win is
a code-quality and allocation-pressure improvement; not a
frame-rate move on this class of hardware.
